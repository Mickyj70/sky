# Sky v0.2.0-rc.1

First source release candidate for the saved-tracking milestone. This candidate is for evaluation and feedback; it is not stable 1.0 and does not include prebuilt platform binaries.

## Included

- Plane registration/ICAO hex, callsign, nearby and regional operator-prefix lookups.
- Human-readable tables, documented lookup JSON and typed failure/exit behavior.
- Persistent SQLite watchlists with normalized, idempotent add/list/remove commands.
- Consistent snapshot backup and validated non-overwriting restore.
- Bounded foreground polling with cooldowns/backoff, freshness states, repeat suppression and NDJSON events.
- Request/time budget visibility, output-failure handling and Ctrl-C cancellation.
- Provider redirect rejection and existing-database validation without unnecessary writer-lock contention.
- Unified CLI/provider release identity and repeatable clean-source/recovery validation.

## Install from tagged source

Once the candidate tag is published, Go 1.24+ can build it:

```sh
go install github.com/Mickyj70/sky/cmd/sky@v0.2.0-rc.1
sky --version
```

Expected version: `sky version 0.2.0-rc.1`. Normal builds require no CGO toolchain. Add your Go binary directory to PATH if needed.

## Try it

```sh
sky watch add --registration G-ZBKE
sky watch list
sky watch run --interval 5m --max-requests 10 --json
```

The budget is required and scoped to one foreground run, not a shared daily account/IP quota. Targets are loaded once; restart to pick up edits. `missing` means no matching provider observation, not landed. Recoverable provider failures can consume the budget and still end with exit 0; inspect error events for availability.

## Validation and compatibility

The release-preparation PR records native validation and hosted CI evidence. Run `scripts/validate_release.py` to reproduce checks and produce a JSON report with exact source commits, toolchain and platform. CI preserves its report artifact for 30 days.

Schema 1 is unchanged. The validation runner exercises both-way reading/writing and snapshot recovery with `checkpoint/watchlists-review-2026-11-17`, an earlier unreleased schema-1 source checkpoint. This is not a claim of universal binary downgrade compatibility. Back up before an upgrade and restore into a new directory if recovery is needed.

Validation uses local fixtures rather than public provider quota. Native platform scope is recorded in the report; earlier cross-builds do not certify every OS runtime. Windows contributor documentation is still tracked separately in PR #15.

## Limits and what comes next

- Provider receiver coverage/freshness varies. Data is not authoritative scheduled flight status.
- Registration and hex aliases remain separate saved targets.
- Watch states are evaluated at poll completion; there is no continuously aging dashboard.
- Restore requires a filesystem that supports hard links.
- No persisted aircraft observation history, history exports, daemon or notifications yet.
- Complete airline fleets, dated flights/codeshares and commercial provider selection remain M3.
- Binary packaging/checksums and broader native platform testing remain M4.
- CLI version is centralized in source; richer build-time commit metadata remains distribution work.

The next implementation milestone is M2: observation history, retention and export, with explicit migration/backup compatibility. Stable release and any later candidate will use new immutable tags; this candidate tag must never be moved.
